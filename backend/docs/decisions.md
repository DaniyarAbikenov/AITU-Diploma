# Архитектурные решения бэкенда

| Решение | Почему | Что дальше |
|---|---|---|
| Деньги хранятся целыми в тиынах, наружу отдаются в тенге | нет ошибок округления float | без изменений |
| SQLite по умолчанию, PostgreSQL через `DATABASE_URL` | запуск без установки сервера, быстрые тесты | проверить на PostgreSQL |
| `create_all` при старте вместо Alembic | схема ещё меняется, один день на каркас | подключить Alembic до первой реальной БД |
| Модель прогноза `fc-1.0-bootstrap`: выборка из собственных дневных трат по дням недели | объяснима, не требует обучения, хватает 3–4 месяцев данных | сравнить с наивным базовым прогнозом на отложенной выборке (план оценки) |
| Общие случайные числа для базы и сценария | разница сценария не зашумлена случайностью | без изменений |
| `p_shortfall` = доля траекторий, где баланс хоть раз ниже 0 за горизонт | прямое определение вероятности кассового разрыва | валидация по CFPB Financial Well-Being Scale |
| Веса индекса: разрыв .25, подушка .25, DTI .20, волатильность .10, стабильность дохода .10, доля валюты .10 | экспертная стартовая оценка | калибровка по опросу |
| Импорт демо идёт через синтетический парсер и настоящий пайплайн | проверяет дедупликацию и категоризацию без реальных выписок | парсеры Halyk и Freedom |
| Парсер Kaspi читает PDF через pdfplumber по координатам слов (колонки берутся из заголовка таблицы) | в текстовом слое нет разделителей; координаты устойчивее регулярных выражений по тексту | сверка суммы операций с остатками на начало и конец периода, несошедшееся попадает в `warnings` |
| Операции между своими счетами Kaspi (Kaspi Pay, Депозит) помечаются `internal` сразу при разборе, платёж по кредиту нет | иначе перевод 100 000 ₸ на депозит выглядел бы расходом | то же правило для других банков |
| Регулярный платёж по кредиту распознаётся по двум месяцам подряд, если платёж был за последние 45 дней | суммы меняются при смене кредита, трёх одинаковых месяцев может не быть | сверить на выписках других людей |
| Курс USD/KZT берётся с nationalbank.kz при старте и раз в час (`NBK_RATES_INTERVAL`), прошлые месяцы по курсу на последний день месяца, источник `nbk` | официальный курс, RSS НБ РК открыт и стабилен | при недоступности НБ РК остаются прежние значения |
| Остальные макро-ряды и цены по городам помечены `demo-seed` | нет автоматического источника, НБ РК не отдаёт всё в одном API | CPI из бюллетеней БНС |
| Валютные счета (KZT, USD, EUR, RUB): деньги счёта, его checkpoint и операции хранятся в валюте счёта в minor units этой валюты (`balance_minor`, `amount_minor` + `currency`); существующие поля API не меняют смысла — `balance`/`amount` в валюте счёта/операции | тенге-эквивалент зависит от курса и не должен «застывать» в данных | эквиваленты `balanceKzt`, `currentBalanceKzt` считаются при чтении по последнему официальному курсу |
| Курсы НБ РК всех поддерживаемых валют хранятся в `fx_rates` (последний) и `fx_rate_history` (по дате публикации); `GET /rates` отдаёт курс, дату публикации, время получения и `stale` | НБ РК публикует один официальный курс в день; честно показываем дату | рыночный курс в течение дня — только по отдельному согласию (платный API с ключом) |
| Итоги (капитал, ликвидные деньги, прогноз) считаются в тенге с пересчётом валютных счетов; переоценка `revaluationKzt` = остаток × (курс сейчас − курс на дату остатка) показывается отдельно | валюты не суммируются без конвертации; изменение курса — не доход и не расход | история курсов копится с момента включения |
| Доступность денег счёта: `frozen_until` + `frozen_minor` (NULL = весь остаток); тип счёта `deposit`, ставка и условие досрочного снятия — справочно | замороженные деньги — твои: входят в капитал, но не в ликвидный пул, «свободно на день» и резерв в днях до даты (BR-11, BR-14) | прогноз (Монте-Карло) считает от доступных денег; разблокировка — событие в календаре |
| Перевод между своими счетами — две операции с общим `transfer_group`, `internal=True`, тип `transfer_own`; `POST /transfers` пишет обе в одном commit, `requestId` защищает от дубля | перевод не доход и не расход, капитал не меняется | удаление одной ноги удаляет обе |
| Пары из выписок связываются автоматически только при однозначном совпадении (одна сумма, разные счета, ±1 день, одна пара); остальные ждут подтверждения (`GET /transfers/candidates`, `POST /transfers/link`) | ошибочная автосвязь прячет реальный расход (FR-18) | — |
| Проценты по депозиту — отдельный тип дохода `income_interest` | это доход, а не возврат своих денег | — |
| Ошибки в формате `application/problem+json` | фронтенд читает `detail`, затем `title` | без изменений |

## Дополнения к docs/api-requests.md фронтенда
- `POST /auth/register`, `POST /auth/login`, `GET/PATCH/DELETE /me`: сейчас фронтенд использует мок-авторизацию, нужно подключить. Токен возвращается в теле (`Authorization: Bearer`), httpOnly cookie пока нет.
- `DELETE /obligations/{id}`.
- `POST /imports`: JSON `{"bank": "..."}` запускает демо-импорт; multipart с полями `bank` и `file` читает PDF Kaspi Gold. Ответ содержит необязательное поле `warnings` (например, несходимость с остатками).
- `POST /scenarios/run` принимает `days`.
- `GET /obligations/dti-history` реализован.
