# Financial Life Navigator

Navigator — единственный интерфейс приложения. Главная, вход, регистрация и онбординг оформлены в его стиле (токены — `src/components/navigator/tokens.css`), после входа открывается `/navigator`. Старые адреса (`/dashboard`, `/expenses`, `/debts`, `/forecast`, `/goals`, `/macro`, `/resilience`, `/scenarios`, `/settings`) перенаправляют на нужную вкладку (`/navigator?tab=…`).

Вкладки: Обзор (свободно на день, счета, устойчивость, прогноз месяца, главные выводы), Цели, Операции (история, ручной ввод, импорт выписки, проверка категорий, правила, сравнение месяцев), Календарь (доходы, обязательные и плановые), Прогноз (баланс 30/60/90 с днями риска, устойчивость по компонентам, сценарии), Долги (платежи на 12 месяцев, КДН, симулятор рассрочки), Макро (индикаторы, личная инфляция, цены по городу), Мой прогресс, Профиль (план, счета, обязательные, экспорт, удаление данных, выход).

Доступен по `/navigator`. Два режима (FR-01), переключатель и метка режима — в верхней панели каждого экрана:

- **Демо** — вымышленный пользователь в `localStorage`, дата зафиксирована на 27.11.2026. Работает без входа; описание ниже.
- **Мои данные** — данные вошедшего пользователя с сервера (`/api/v1`), «сегодня» — по часовому поясу профиля (по умолчанию Asia/Almaty). Демоданные сюда не переносятся. Без входа экран предлагает войти (`/login?next=/navigator`).

## Режим «Мои данные»

- Профиль: имя, город, часовой пояс, плановый доход, обязательные расходы, рабочие часы (`GET/PATCH /me`). Пустое поле = «не указано», а не 0.
- Счета: тип (текущий / накопительный / наличные), подтверждение пользователем, остаток как checkpoint на дату — из шапки выписки или введённый вручную (`POST/PATCH /accounts`, `POST /accounts/{id}/checkpoints`). Неподтверждённые счета и счета без известного остатка в расчёты не входят.
- Операции: `/transactions` с фильтрами по месяцу, банку, счёту и типу. Тип операции можно задать вручную (расход, доход/зарплата/другое, перевод между своими счетами, перевод другому человеку) — решение хранится на сервере поверх импорта, оригинал не меняется; можно применить ко всем операциям мерчанта и будущим импортам (`PATCH /transactions/{id}/kind`). Переводы между своими счетами не считаются ни доходом, ни расходом.
- Календарь: найденные регулярные платежи и выплаты дохода, кнопки «Подтвердить» / «Отклонить». Выплат дохода может быть несколько в месяц, у суммы — диапазон (минимум для осторожного плана).
- Цели: только из `/goals`, суммы и сроки вводит пользователь.
- «Свободно на день» (BR-10–13, `src/lib/safe-to-spend.ts`): горизонт — до дня перед ближайшей подтверждённой выплатой дохода (без неё — до конца месяца); `SafeDaily = floor(max(0, min F(d)/d))`, где `F(d)` — деньги на подтверждённых текущих счетах и наличными минус подтверждённые платежи по день d; дефицит = `max(0, −min F(d))`. Резерв в днях (BR-14) = накопительные счета ÷ (обязательные расходы / 30), не считается, пока расходы не указаны. Всё помечено «предварительно».
- Индекс устойчивости и прогноз — с сервера (`/resilience`, `/forecast/balance`), только когда есть подтверждённые счета и операции.
- Ввод данных (CRUD):
  - «Добавить операцию» в шапке любого экрана — ручная операция (тип, сумма, дата, счёт, категория, описание). Клик по операции во вкладке «Операции» открывает её: ручную можно изменить или удалить; операцию из выписки можно скорректировать (сумма, дата, категория, комментарий — оригинал сохраняется, видна история изменений) или отменить / вернуть.
  - «Календарь» → «Доходы» (выплаты, диапазон суммы), «Обязательные платежи» (ежемесячно; разовый или ежегодный обязательный платёж сохраняется как плановая статья), «Плановые статьи» (разовые и ежегодные расходы и доходы, интервал дат, обязательная / можно перенести, счёт) с кнопкой «Отметить оплату»: частичная оплата, привязка уже существующей операции без второго списания. Обязательные платежи можно править и в «Профиле».
  - Ручные операции после даты остатка двигают текущий остаток счёта; неоплаченная часть плановых расходов уменьшает «свободно на день».
- Тексты интерфейса — `src/i18n/ru.ts`.

Тестовый пользователь на синтетике (реальные выписки не нужны):

```sh
cd backend && python -m app.dev_user          # navigator-test@example.com / test12345
python -m app.dev_user --reset                # пересоздать его данные
```

Из `frontend/`:

Откройте `/navigator` на адресе, который напечатает Vite. Сборка `npm run build`; проверки `npm test` и `npx tsc --noEmit`. Используются существующие React 19, TanStack Query/Router, Radix Dialog, ECharts. Бэкенд для демо не нужен. Основное приложение и `VITE_API_MODE=real` сохранены.

## Что можно показать

1. Обзор: доступная дневная сумма, устойчивость, капитал, резерв, цели и прогноз.
2. Добавить расход 1 000 ₸: текущий счёт уменьшится с 485 000 до 484 000 ₸; цели не изменятся. Нажать операцию, исправить сумму или удалить с подтверждением.
3. Пополнить резерв на 10 000 ₸: текущий счёт уменьшится, накопительный увеличится. Капитал останется 9 610 000 ₸. Перевод можно отменить через историю операций.
4. Создать цель и сравнить планы «Параллельно» / «Сначала резерв». Смена стратегии изменяет оценки срока; автоматические платежи не запускаются.
5. Посмотреть календарь будущих зарплат и платежей; поиск и фильтры операций; расходы по категориям.
6. Установить три месяца без дохода в прогнозе. Проверить снижение капитала и число дней покрытия обязательных расходов резервом.
7. Пройти урок, получить XP один раз; закрыть и открыть страницу — состояние сохранится.
8. В профиле изменить доход и расходы; сбросить только данные этого демо с подтверждением.

## Модель и ограничения

- Дата фиксирована: **27 ноября 2026**, модель `navigator-demo-v1`. Все суммы в целых тенге.
- Текущий счёт определяется начальным остатком и журналом операций. Накопительный счёт — начальным остатком и внутренними переводами. Суммы целей являются распределением внутри накопительного счёта: двойного учёта нет.
- Начальные цели: квартира 7 200 000 ₸, авто 1 800 000 ₸, резерв 125 000 ₸. В отличие от несогласованного JSON в концепции, накопительный счёт равен их сумме: 9 125 000 ₸.
- Свободно сегодня = `max(0, текущий счёт − 137 800) / 28`, округление вниз. Фиксированные обязательства и дни относятся к демоснимку. Будущие добровольные взносы в цели здесь не резервируются.
- Резерв = средства резервной цели, а не все накопления. При расходах 250 000 ₸/мес. начальный резерв покрывает **15 дней**.
- Шкала устойчивости: до 60 баллов за 90 дней резерва, до 25 за долю свободного дохода, 15 за покрытие ближайших обязательств. Это прозрачная эвристика, не валидированный рейтинг.
- Прогноз: начальный капитал + доход − обязательные и дополнительные расходы. Диапазон соответствует расходам ±20%; это чувствительность к предположениям, **не доверительный интервал**. Доходность, инфляция и налоги не моделируются.
- Календарь — отдельный демонстрационный план фиксированных событий. Каждый выбранный месяц начинается с текущего баланса; повседневные траты не включены. Это явно подписано на экране.
- XP не меняет финансовые показатели. Отметка проверки подписок не создаёт вымышленную экономию. Нет штрафов за неактивность.
- Хранение: `localStorage`, ключ `financial-life-navigator-v1`. Схема проверяется Zod. Ошибка чтения/записи показывается пользователю; есть восстановление демо. Синхронизация между вкладками через `storage` event.
- API для демо проходит через `src/api/client.ts` и `q.navigator`, но намеренно изолирован от реального банковского режима. Он не отправляет сетевые запросы, не выполняет финансовые операции и не изменяет существующую БД.

Импорт банковских выписок, долговая аналитика и макроэкономика остаются в основном приложении. В Navigator пока нет банковской интеграции, серверной синхронизации, импорта выписок, полноценного редактора платежного календаря или ML-прогнозов. Это демонстрация ключевых интерактивных сценариев, а не готовый банковский продукт.

## Проверки

Тесты бизнес-логики покрывают сохранение капитала при переводе, отмену, недостаток средств, исправление расходов, календарные даты, однократное начисление XP и стресс-сценарий. Интеграционные тесты проверяют сохранение после перемонтирования, ошибку записи в хранилище, прохождение урока и маршрут `/navigator`. ECharts в UI-тестах замокан; визуальная проверка в реальном браузере нужна отдельно.
